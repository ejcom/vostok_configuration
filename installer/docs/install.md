## Запуск и режимы проверки

Нужна Debian-подобная система (Armbian, Raspberry Pi OS, BTT Pi и т. п.), обычный пользователь с `sudo`, интернет и подключённые по USB платы. Питание 24 В для прошивки по USB не нужно: платы голов по умолчанию прошиваются «на столе» по DFU. Источник 24 В и CAN-кабели нужны только для варианта «Klipper по CAN» и для проверки `canbus_uuid` после установки электроники в принтер.

```bash
git clone https://github.com/dmitry-sorkin/vostok_configuration.git
cd vostok_configuration/installer

./install_vostok.sh --only-detect   # что видит скрипт, ничего не меняет
./install_vostok.sh --dry-run       # все шаги и команды без изменений
./install_vostok.sh                 # установка

./configure_vostok.sh --dry-run     # только настройка конфига, без установки и прошивки
```

Каталог клона должен остаться на месте: кнопка обновления запускает скрипты из него. Если установщик запущен из клона, конфигурацию принтера он берёт оттуда же (удобно проверять форки и PR); иначе скачивает `main`. Переменная `VOSTOK_CFG_LOCAL=0` заставляет всегда скачивать, `VOSTOK_CFG_LOCAL=/путь` — взять свой каталог.

## Что делает установщик

1. Проверки и пакеты (`apt`: git, dfu-util, gcc-arm-none-eabi, python3-serial и др.).
2. KIAUH → Klipper (форк `dmbutyugin/klipper`, ветка `generic-cartesian`), Moonraker, Fluidd; расширение `gcode_shell_command`; katapult. Если `~/klipper` уже есть, но не форк, предложит переключить.
3. Определяет платы (`/dev/serial/by-id`, режим DFU, мост USB-CAN), спрашивает о том, что определить нельзя (главная плата, платы голов, число ALPS), показывает план.
4. Если есть платы голов — спрашивает, как их прошивать (`--heads-flash`), и настраивает `can0` (`/etc/network/interfaces.d/can0`, 1 Мбит, `txqueuelen 128`).
5. Прошивает платы по очереди и на каждом шаге говорит, что сделать руками:
   - **ALPS**: BOOT + RESET → DFU → katapult → Klipper;
   - **платы голов** — способ на выбор (`--heads-flash`):
     - **`dfu` — «на столе» (по умолчанию, в том числе с `-y`)**: по одной плате, подключённой только по USB, BOOT0/BOOT + RESET → DFU → katapult и Klipper за один сеанс. 24 В и CAN не нужны, поэтому все платы можно прошить до установки в принтер. `canbus_uuid` без шины узнать нельзя, поэтому установщик читает UID чипа по DFU и вычисляет `canbus_uuid` по тому же алгоритму, что и прошивка; UUID моста считается по USB-serial Octopus. Эти значения попадают в `printer.cfg` и `devices.tsv`, но **на шине не проверены**: после установки электроники в принтер подайте 24 В и выполните `./install_vostok.sh --check-can` (см. ниже). Если UID прочитать не удалось, в `printer.cfg` остаётся `ЗАПОЛНИТЕ`;
     - **`can` — для собранного принтера**: BOOT0/BOOT + RESET → DFU → katapult, затем Klipper по CAN с проверкой через `canbus_query.py`. **Нужны источник 24 В и подключение плат голов и Octopus по CAN** — установщик предупреждает об этом до начала прошивки;
   - **Octopus**: джампер BOOT0 + RESET → DFU. Способ на выбор: **katapult и Klipper сразу по DFU за один сеанс (рекомендуется, по умолчанию)** или katapult по DFU, затем Klipper через katapult (потом снять джампер). Klipper — для USB или моста USB→CAN.

   Если прошивка платы не удалась, меню предлагает повторить, прошить katapult и Klipper сразу по DFU, прошить заново через katapult, прошить только Klipper по DFU, пропустить плату или прервать установку — это работает для всех плат.

   Если на плате уже есть katapult или Klipper, на запросе DFU введите `s` + Enter и дважды быстро нажмите RESET.
6. Конфигурация принтера. Спрашивает, откуда взять конфиг электроники:
   - **стандартный** (корень репозитория, поддерживается автором) или **пользовательский** (`user_configs/`; перед выбором сверьте схему подключения в начале файла — неверная схема может вывести электронику из строя);
   - **сгенерировать свой конфиг**: шаблон без плат и драйверов + пресеты найденных плат + мастер выбора драйверов; пины и параметры берутся из вашего текущего конфига, а при чистой установке H723 — из стокового main;
   - **пропустить редактирование конфига** (только если `printer.cfg` уже есть, по умолчанию): дописываются только недостающие `[mcu …]`.

   Затем спрашивает про дополнительные модули (например, `chamber_heater.cfg`) и проверяет пересечения пинов. Подробности и все правила: [CONFIGURATOR.md](../CONFIGURATOR.md). Файлы копируются в `~/printer_data/config`, прежние сохраняются как `*.bak-<дата>`.
7. Запускает Klipper, сверяет версии прошивок, ставит кнопку обновления и тему Fluidd.

После установки вручную: сверить `electronics_*.cfg` со своей проводкой (у сгенерированного файла — вписать пины с пометкой `ЗАПОЛНИТЕ` и проверить блоки с `СВЕРЬТЕ`), проверить термисторы голов (возьмите термистор пальцами — температура должна расти у нужной головы, иначе поменяйте местами секции `T0…`/`T1…`), для ALPS добавить `[load_cell_probe]` и выполнить `LOAD_CELL_CALIBRATE`.

## Опции `install_vostok.sh`

| Опция | Назначение |
|---|---|
| `--main h723\|f446` | главная плата (иначе определит/спросит) |
| `--heads none\|v1.3\|v2\|ebb42` | платы голов (`--h36` — прежнее имя) |
| `--alps 0\|1\|2` | число ALPS |
| `--heads-flash dfu\|can` | способ прошивки плат голов: `dfu` — «на столе», katapult и Klipper по USB без 24 В и CAN (по умолчанию, с `-y` тоже); `can` — katapult по DFU, Klipper по CAN (нужны 24 В и CAN-кабели) |
| `--check-can` | после установки электроники в принтер: прочитать `canbus_uuid` с шины CAN (нужны 24 В), сверить с вычисленными, исправить `devices.tsv` и `printer.cfg`, перезапустить Klipper; ничего не прошивает |
| `--config-source standard\|user\|generate\|skip` | источник конфига: корень репозитория, `user_configs/`, сгенерировать свой или пропустить редактирование |
| `--drivers СПЕК` | драйверы для `generate`: `all=2130\|2208\|2209\|2240\|5160\|5160plus` или `x=5160,w=5160,yl=5160,yr=5160,z=2209,e0=2209,e1=2209` (без опции — диалог, с `-y` — как в стоковом конфиге) |
| `--reference ФАЙЛ\|none` | эталон пинов и параметров для сгенерированного конфига: по умолчанию ваш текущий electronics-файл, при чистой установке стоковый main (H723) |
| `--modules ИМЕНА` | дополнительные модули без вопроса: `chamber_heater`, `all` или `none` |
| `--main-flash dfu\|katapult` | способ прошивки главной платы: katapult и Klipper сразу по DFU (рекомендуется) или katapult по DFU + Klipper через katapult |
| `--electronics ФАЙЛ` | конкретный `electronics_*.cfg` |
| `--only-detect` | только определить платы и показать план |
| `--dry-run` | показать шаги и команды, ничего не менять |
| `--skip-software` / `--skip-flash` / `--skip-config` / `--skip-button` / `--skip-theme` | пропустить этап |
| `--skip-board ПЛАТА` | не прошивать уже прошитую плату: `alps`, `alps0`, `alps1`, `main` или `heads` (можно повторять) |
| `--reflash` | не предлагать пропуск, прошить все платы заново |
| `--upgrade` | `apt upgrade` перед установкой |
| `-V`, `--version` | показать версию установщика (текущая: 1.2c, файл `VERSION`) |
| `-y` | не задавать вопросов, где есть ответ по умолчанию (шаги с железом всё равно ждут Enter) |

## После установки электроники в принтер (платы голов, прошитые на столе)

1. Подключите платы голов и Octopus по CAN, подайте 24 В.
2. Выполните `./install_vostok.sh --check-can`. Скрипт остановит Klipper, поднимет `can0`, найдёт платы на шине и сверит их `canbus_uuid` с вычисленными по UID. Совпавшие подтверждаются; если какая-то плата отвечает под другим UUID или UUID был неизвестен, скрипт определяет, какая плата левая (T0), а какая правая (T1), по очереди отключая CAN-кабель, и записывает найденные значения в `devices.tsv` и `[mcu]`/`[mcu T0…]`/`[mcu T1…]` в `printer.cfg` (с резервной копией), затем запускает Klipper.
3. То же вручную: остановите Klipper, выполните `~/klippy-env/bin/python ~/klipper/scripts/canbus_query.py can0`, впишите `canbus_uuid` в `printer.cfg` и запустите Klipper.

Лог: `~/printer_data/logs/vostok_install.log`. Установка повторяема: уже сделанное пропускается.
