## Не подтверждено / риски
- Gen2: offset 8KiB и способ входа в DFU для Gen2 явно не найдены (страницы Gen2 на bttwiki не прочитались); CAN PB12/PB13 только из sample-cfg BTT.
- SHT36 v2: APM32F072 в DFU показывается как USB ID 314b:0106 (teamfdm), а установщик ищет 0483:df11 (`hardware.dfu_count`, `flashing.py`) и определяет семейство по Option Bytes ST. Для APM32 DFU-прошивка через установщик, скорее всего, не сработает; прошивка по CAN в заводской Katapult возможна. GD32F103 (ранние партии) требует stm32f103, не добавлен. Скорость CAN: у Mellow 500K (статья CanBoot) / 1M (завод), в `.board` 1M.
- Светодиод katapult PC13 у SHT36 v2 назван одним источником: `KATAPULT_LED` пуст.
- INITIAL_PINS (безопасное состояние нагревателя в DFU) не заданы: пины нагревателя не подтверждены (у EBB v1.1 известен PA2 в DFU, у Gen2 не проверено).
- ELEC_PATTERN/TEMPLATE пусты: стоковых `electronics_*.cfg` и пресетов `boards/*.cfg` для голов нет.

## Не добавлено: плата не подходит под код установщика
- **FLY SHT36 v3 / SHT36 Max v3: RP2040.** mellow.klipper.cn/en/docs/ProductDoc/ToolBoard/fly-sht36/sht36_v3: "Raspberry Pi RP2040, dual-core Cortex-M0+ 133 MHz"; страница CAN-прошивки v3: offset 16 KiB, CAN RX/TX GPIO 1 и 0 (опции RPXXXX_CANBUS_GPIO_RX/TX в klipper/src/rp2040/Kconfig). SHT36 Max v3 отдельно не проверялся.
- **MKS THR36/THR42: RP2040** (github.com/makerbase-mks/MKS-THR36-THR42-UTC: THR42 на RP2040 + TMC2209, с завода USB-прошивка, отдельная CAN-прошивка). CAN-пины и загрузчик не найдены.

## RP2040: что нужно доработать (для интегратора, код B4 не менял)
Установщик не умеет такой FAMILY: допустимо `f0|f4|h7|g` (docs/build-configs.md; `hardware._FAMILY_NAMES`, `_UID_ADDR`, `dfu_family` по ST Option Bytes). Нужно:
1. `vostok/boards.py` и `tools/gen_configs.py`: FAMILY `rp2040`; Kconfig для RP2040 (`MACH_RP2040`, `RPXXXX_CANBUS`, `RPXXXX_CANBUS_GPIO_RX/TX`, смещение 16 KiB, flash chip); сейчас генератор рассчитан на STM32 (CLOCK_REF, `STM32_*CANBUS_*`).
2. `vostok/hardware.py`: обнаружение BOOTSEL вместо `lsusb -d 0483:df11` (USB ID ROM RP2040: 2e8a:0003), `dfu_family`/`family_name`/`uid_addr` для rp2040.
3. `vostok/flashing.py`: прошивка по BOOTSEL (UF2 на диск RPI-RP2 или `picotool`), без `dfu-util`; Katapult для RP2040 собирается в `katapult.uf2`.
4. Чтение UID для canbus_uuid сейчас идёт через DFU-адрес чипа: для RP2040 нужен другой способ (или опрос по CAN после запуска Katapult).

## Общий блокер для всех трёх плат: `--heads` зашит в коде
`--heads` принимает только `none|v1.3|v2|ebb42` (`vostok/install.py` HEADS_VALUES, строки 73/150/856; `vostok/electronics.py` HEADS_CHOICES/HEAD_FILE, строки 77-80, 486; `vostok/configurator.py` HEADS_VALUES/HEAD_VERSIONS, 1273). Поэтому `install_vostok.sh --dry-run --heads <новый id>` отвечает "ОШИБКА: --heads: none, v1.3, v2 или ebb42". Новые головы видны в реестре (`--list-boards`), но выбрать их нельзя. Доработка: брать допустимые значения из реестра (`ROLE=head`, id и алиасы) и шаблон `boards/<pattern>.cfg` для секций `[mcu T0_EBB]` и т. п.
