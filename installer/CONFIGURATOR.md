# Конфигуратор VOSTOK (`configure_vostok.sh`)

🇷🇺 Русский | [🇬🇧 English](CONFIGURATOR.en.md)

Конфигуратор настраивает конфигурацию принтера отдельно от установки: выбирает или генерирует `electronics_*.cfg`, подбирает драйверы моторов, дописывает недостающие секции `[mcu …]` в `printer.cfg`, подключает дополнительные модули и проверяет, что пины не повторяются. Прошивку плат и установку ПО он **не** трогает: для них есть [`install_vostok.sh`](README.md). Тот же код выполняется и на этапе конфигурации установщика, поэтому всё описанное здесь верно для обоих скриптов.

## Для чего

Запускайте конфигуратор, когда:

- поставили свои драйверы вместо стоковых (TMC2209, TMC5160 и т. д.) и нужен конфиг под них;
- проводка отличается от стока (другие разъёмы, головы подключены прямо к Octopus, платы EBB42 вместо H36);
- подключили новую плату (второй ALPS, платы голов) и её `[mcu …]` нет в `printer.cfg`;
- хотите подключить дополнительный модуль, например подогрев термокамеры `chamber_heater.cfg`;
- ставите систему с нуля: на этапе конфигурации установщик вызывает то же самое.

## Быстрый старт

```bash
cd ~/vostok_configuration/installer

./configure_vostok.sh --dry-run          # показать, что будет сделано, ничего не менять
./configure_vostok.sh                    # диалог: источник конфига, драйверы, модули
./configure_vostok.sh -y --config-source generate --drivers all=2209 --modules chamber_heater   # без вопросов
```

Нужны `python3` и каталог `~/printer_data` (другой — `--printer-data`). После записи конфига перезапустите Klipper (`RESTART` в Fluidd или `sudo systemctl restart klipper`). Лог: `~/printer_data/logs/vostok_configure.log`.

## Как это работает

1. **Определение железа.** Главная плата, платы голов, число ALPS: из опций, из текущего `printer.cfg`, из `/dev/serial/by-id`, иначе вопросы.
2. **Сбор значений `[mcu]`.** Серийные номера и UUID берутся из `printer.cfg`, `devices.tsv` и `/dev/serial/by-id`.
3. **Меню источника конфига.** Стандартный, пользовательский, сгенерировать, пропустить.
4. **Для «сгенерировать»:** выбор драйверов (мастер или `--drivers`), поиск эталона, генерация `electronics_<…>.cfg` в временный каталог.
5. **Запись.** Состояние `printer.cfg` определяет режим. **Чистая установка** (файла нет, он пустой или это не конфиг VOSTOK без `[include printer_base.cfg]`, например пример KIAUH): из main копируются `printer.cfg`, `printer_base.cfg`, `chamber_heater.cfg`, `postprocessing/` и выбранный `electronics_*.cfg`, прежний файл сохраняется как `*.bak-<дата>`. **Существующий конфиг VOSTOK**: записывается только новый `electronics_*.cfg`, в `printer.cfg` меняются лишь набор `[mcu …]` и строка `[include electronics_….cfg]`; `printer_base.cfg`, `chamber_heater.cfg`, `postprocessing/` не трогаются (докопируются, только если их нет), блок `SAVE_CONFIG` и остальные настройки остаются. Перед записью `printer.cfg` и одноимённый electronics-файл сохраняются как `*.bak-<дата>`.
6. **Дополнительные модули.** Вопрос по каждому, проверка пересечений пинов, подключение `[include …]`.
7. **Проверка пересечений** пинов во всём конфиге и итоговые предупреждения.

В режиме `--dry-run` выполняются шаги 1–4 и 6–7 (без записи), печатается всё, что было бы записано.

## Определение железа

Приоритет источников:

1. опции `--main`, `--heads`, `--alps`;
2. существующий `printer.cfg` и подключённые им файлы:
   - главная плата: `stm32h723xx` / `stm32f446xx` в `serial` секции `[mcu]` или `_h723_` / `_f446_` в имени подключённого electronics-файла;
   - платы голов: секции `[mcu T0_EBB]` → EBB42; `[mcu T0CB]` → H36 (v2, если в имени electronics-файла есть `H36v2`, иначе v1.3); если есть только USB-`[mcu]`, голов нет;
   - ALPS: число секций `[mcu alps…]` (не больше двух);
3. `/dev/serial/by-id` (`usb-Klipper_stm32h723xx_…`, `usb-Klipper_stm32f072xb_…`) и режим DFU;
4. вопросы в диалоге (с `-y` берётся значение по умолчанию).

Значения для блоков `[mcu …]` (serial и `canbus_uuid`) берутся в таком порядке: текущий `printer.cfg` → `devices.tsv` (его пишет установщик) → `/dev/serial/by-id`. Если значения нет, в блоке стоит `ЗАПОЛНИТЕ`; такой блок в существующий `printer.cfg` не добавляется (только печатается предупреждение), а в новый записывается как заглушка, на которой Klipper сообщит об ошибке, пока её не заменят.

## Источники конфига

| Пункт меню | Что делает |
|---|---|
| **Стандартный (корень main)** | копирует `electronics_*.cfg` из корня репозитория (поддерживается автором) |
| **Пользовательский (user_configs)** | копирует один из файлов `user_configs/`; перед использованием сверьте схему подключения в начале файла: неверная схема может вывести электронику из строя |
| **Сгенерировать свой конфиг** | собирает файл из шаблона без плат и драйверов и пресетов найденных плат, см. ниже |
| **Пропустить редактирование конфига** | доступен, если `printer.cfg` уже есть и выбран **по умолчанию**; дописывает только недостающие `[mcu …]`, см. следующий раздел |

Для первых трёх пунктов при чистой установке копируются `printer.cfg`, `printer_base.cfg`, `chamber_heater.cfg`, выбранный `electronics_*.cfg` и `postprocessing/`; у существующего конфига VOSTOK пишется только `electronics_*.cfg` (см. «Как это работает», п. 5). В `printer.cfg` подставляются найденные `[mcu]`, `[mcu T0CB]`/`[mcu T1CB]` (для EBB42 — `T0_EBB`/`T1_EBB`) и `[mcu alps]`/`[mcu alps_t1]`. Файл можно задать сразу: `--electronics ИМЯ.cfg`, источник — `--config-source standard|user|generate|skip`.

Без терминала и без `--config-source` при существующем `printer.cfg` выбирается «Пропустить» (конфиг не заменяется).

## Режим «Пропустить»

Служит, когда конфиг вас устраивает, а нужно лишь добавить прошитую плату. Работает `tools/mcu_merge.py`; для каждой платы из списка найденных он печатает один из результатов:

| Результат | Что значит |
|---|---|
| `OK` | такая секция уже есть (сравнивается значение `serial`/`canbus_uuid`, даже если секция названа иначе), ничего не делается |
| `ADD` | секции нет, она добавляется после последней `[mcu …]` самого `printer.cfg` |
| `DIFF` | секция с таким именем есть, но значение другое: файл **не меняется**, вы видите оба значения и решаете сами |
| `TODO` | плата не прошита (`ЗАПОЛНИТЕ`), секция не добавляется |

Всё остальное в `printer.cfg` не меняется. Перед записью делается копия `printer.cfg.bak-<дата>`, и только если действительно что-то добавляется. Затем выполняются шаги про модули.

## Эталон: ваш конфиг — основа

**Правило:** если у вас уже есть свой `electronics_*.cfg`, он всегда основа, без вопросов. Стоковый main (для H723) берётся только при первой чистой установке, когда своего конфига нет.

Эталон определяется автоматически:

1. активный `[include electronics_*.cfg]` в `~/printer_data/config/printer.cfg`, если файл существует: это ваш конфиг;
2. иначе, если главная плата H723, — стоковый main из корня репозитория;
3. иначе (F446 без своего конфига) эталона нет: пины остаются пустыми, параметры берутся по умолчанию.

`--reference ФАЙЛ` задаёт другой эталон, `--reference none` отключает эталон полностью. Какой файл взят, конфигуратор сообщает в начале генерации.

Что берётся из эталона (только пины основной платы, то есть без префикса другой MCU вида `T0CB:`; пины плат голов не переносятся):

| Что | Откуда и как |
|---|---|
| `step_pin`, `dir_pin`, `enable_pin` моторов X, W, YL, YR, Z (и экструдеров, если они на основной плате) | из секций `[stepper motor_*]`, `[extruder]`, `[extruder1]` эталона, со знаками `!` |
| пин драйверного разъёма | `cs_pin` или `uart_pin` секции драйвера эталона. Тип драйвера может быть другим: пин переносится между SPI и UART (на Octopus линия UART совпадает с CS) |
| SPI-пины драйверов | `spi_software_sclk/mosi/miso_pin` эталона; если их нет, стоковые PA5 / PA7 / PA6 |
| `run_current`, `stealthchop_threshold`, `interpolate` | из секций `[tmc… ]` эталона по мотору; если в эталоне нет, из стокового main, затем встроенные значения (X/W/YL/YR 1.6 А, Z 1.2 А, экструдеры 0.9 и 0.7 А) |
| прочие пины основной платы: нагреватель и термистор стола и головы, вентиляторы, концевики, подсветка, зонд | если такая же секция и опция есть в сгенерированном файле, значение эталона заменяет пресет |

## Мастер драйверов

Нужен только для «Сгенерировать». В диалоге:

1. «Какие драйверы стоят на плате?» — **Все одинаковые** → выбор типа из списка; либо **Разные драйверы** → тип для каждого мотора по очереди: экструдер T0, экструдер T1 (только если нет плат голов), затем X, W, Y левый, Y правый, Z.
2. Если платы голов есть, драйверы экструдеров **не спрашиваются**: TMC2209 распаян на плате головы и берётся из её пресета.

Без диалога драйверы задаёт опция `--drivers`:

```text
--drivers all=2209                                           # у всех один тип
--drivers x=5160,w=5160,yl=5160,yr=5160,z=2209,e0=2209,e1=2209   # по моторам (e0/e1 при платах голов не нужны)
```

Допустимые типы: `2130`, `2208`, `2209`, `2240`, `5160`, `5160plus` (допустимы также `tmc2209`, `5160pro`, `5160tplus`). С `-y` без `--drivers` берутся драйверы стока: `x, w, yl, yr, z = 2240`, `e0, e1 = 2209`.

## Пресеты драйверов

Значения `sense_resistor` взяты из документации BTT (страницы TMC2130, TMC2208, TMC2209, TMC2240, TMC5160, TMC5160T Plus, TMC5160T Pro V1.0). Пины в пресетах пустые: подставляются из эталона или остаются `ЗАПОЛНИТЕ`.

| Тип | Интерфейс | Пины в секции | `sense_resistor` | Примечание |
|---|---|---|---|---|
| TMC2130 | SPI | `cs_pin`, `spi_software_sclk/mosi/miso_pin` | 0.110 | |
| TMC2208 | UART | `uart_pin` | 0.110 | |
| TMC2209 | UART | `uart_pin` | 0.110 | |
| TMC2240 | SPI | `cs_pin`, `spi_software_*` | не задаётся | в Klipper у tmc2240 он не используется |
| TMC5160 / 5160T Pro | SPI | `cs_pin`, `spi_software_*` | 0.075 | |
| TMC5160T Plus | SPI | `cs_pin`, `spi_software_*` | 0.022 | значение Klipper по умолчанию (0.075) для Plus неверно |

Ток и режимы (`run_current`, `stealthchop_threshold`, `interpolate`) берутся из эталона (см. выше), а **не** из примеров BTT: примеры вроде `run_current: 0.80` годятся только для проверки. Если выбран TMC2130, 2208 или 2209, а ток из эталона больше 1.2 А (например, 1.6 А, рассчитанные на TMC2240), печатается предупреждение: для этих драйверов уменьшите ток (обычно 0.8–1.2 А). Диагностические пины (`diag1_pin`, `driver_SGT`) в пресеты не входят: бессенсорных концевиков в этом конфиге нет.

## Пресеты плат

Накладываются на шаблон `templates/electronics_blank.cfg` в этом порядке: Octopus Pro, затем платы голов.

- **Octopus Pro по гайду** (`templates/boards/octopus_pro.cfg`): концевики Y (`PG6`, `PG9`), нагреватель и термистор стола (`PB0`, `PF3`), вентилятор модели (`!PD12`), вентилятор отсека электроники (`PD13`), подсветка (`PB11`). Это стоковая проводка H723.
- **Fysetc H36 v1.3 и v2** (`h36_v1.3.cfg`, `h36_v2.cfg`) и **BTT EBB42** (`ebb42.cfg`): по одному блоку на голову (T0 и T1). Содержимое: пины экструдера (step/dir/enable), TMC2209 экструдера (`uart_pin`, `sense_resistor 0.110`), нагреватель, термистор, вентилятор хотэнда, концевик X (для T1 — W), для T0 ещё зонд (`probe`, `probe_enable`), у H36 акселерометры и датчики температуры платы и драйвера, у EBB42 вентилятор платы. Пины сверены со стоковым конфигом и конфигами из `user_configs/`. Имена `[mcu T0CB]`/`[mcu T1CB]` (EBB42: `T0_EBB`/`T1_EBB`) подставляются в пины как префикс.
- **ALPS** (`templates/boards/alps.cfg`): добавляется закомментированный блок `[static_pwm_clock]` и `[load_cell_probe]` с подсказкой. Почему закомментирован: `printer_base.cfg` построен на `[probe]` (виртуальный концевик Z, макросы читают `configfile.config["probe"]`), два зонда конфликтуют. Чтобы использовать ALPS как зонд, закомментируйте `[probe]`, раскомментируйте блок и выполните `LOAD_CELL_CALIBRATE` (потребуется правка `printer_base.cfg`).

## Головы без плат голов

Когда голов на CAN нет (головы подключены прямо к Octopus), в main нужные пины стоят на платах голов (`T0CB:PA8` и т. п.) и использовать их нельзя. Тогда:

**Моторы экструдеров** (если их нет в эталоне, только H723): свободные разъёмы стока.

| Мотор | Разъём | `step` / `dir` / `enable` | `cs`/`uart` драйвера |
|---|---|---|---|
| E0 (левая голова) | MOTOR4 | `PF9` / `PF10` / `!PG2` | `PF2` |
| E1 (правая голова) | MOTOR5 | `PC13` / `!PF0` / `!PF1` | `PE4` |

**Прочие пины голов** берутся с разъёмов самой Octopus Pro (`templates/boards/octopus_heads.cfg`):

| Что | Разъём | Пин |
|---|---|---|
| нагреватель T0 / T1 | HE0 / HE1 | `PA2` / `PA3` |
| термистор T0 / T1 | T0 / T1 | `PF4` / `PF5` |
| вентилятор хотэнда T0 / T1 | FAN0 / FAN1 | `PA8` / `PE5` |
| концевик X / W | STOP2 / STOP3 | `^PG10` / `^PG11` (STOP0/STOP1 в стоке заняты концевиками Y) |
| зонд / включение зонда | BLTouch | `^!PB7` / `PB6` |

**Откуда эта таблица и почему её надо сверять.** Пины взяты из конфигов репозитория для Octopus Pro, где головы на самой плате (`user_configs/electronics_octopus_pro_v1.0_f446_4x5160_3x2209.cfg`), и не сверены с документацией Octopus Pro v1.1 H723. Поэтому:

- каждый блок с такими пинами в файле помечен комментарием `# !!! СВЕРЬТЕ СО СВОЕЙ СХЕМОЙ …`, а в конце запуска печатается предупреждение со списком этих секций;
- если пин из таблицы уже занят другой секцией (эталон, мотор), он **остаётся пустым** с пометкой `ЗАПОЛНИТЕ`, а предупреждение называет, чем он занят. Например, в стоке H723 `PA2` — это `enable_pin` левого мотора Y, поэтому `heater_pin` экструдера T0 остаётся пустым;
- если эталон (ваш конфиг) задаёт такие пины на основной плате, берутся они, а не таблица.

## Имя сгенерированного файла

Имя строится по образцу файлов в `user_configs/`:

```text
electronics_<плата>_<N>x<драйвер>[_<N>x<драйвер>…][_2x<головы>].cfg
```

- `<плата>`: `octopus_pro_v1.1_h723` (H723) или `octopus_pro_v1.0_f446` (F446);
- группы драйверов — число моторов основной платы с этим драйвером, по убыванию числа, затем по названию; при платах голов экструдеры не считаются (их драйверы на платах голов);
- `<головы>`: `H36v1.3`, `H36v2.0`, `ebb42`; без плат голов суффикса нет.

Токены драйверов: `2130`, `2208`, `2209`, `2240`, `5160` (5160 и 5160T Pro), `5160tplus`.

| Конфигурация | Имя файла |
|---|---|
| H723, без голов, все 5160 | `electronics_octopus_pro_v1.1_h723_7x5160.cfg` |
| H723, без голов, X/W/YL/YR — 5160, Z и экструдеры — 2209 | `electronics_octopus_pro_v1.1_h723_4x5160_3x2209.cfg` |
| H723, H36 v2.0, все 2240 | `electronics_octopus_pro_v1.1_h723_5x2240_2xH36v2.0.cfg` |
| H723, EBB42, все 2209 | `electronics_octopus_pro_v1.1_h723_5x2209_2xebb42.cfg` |
| H723, H36 v1.3, все 5160T Plus | `electronics_octopus_pro_v1.1_h723_5x5160tplus_2xH36v1.3.cfg` |

Если файл с таким именем уже есть в `~/printer_data/config`, он сначала сохраняется как `*.bak-<дата>`.

## Структура сгенерированного файла

1. **Шапка**: плата, платы голов, драйверы, пояснение про маркеры.
2. **Двигатели**: `[stepper motor_x]`, `…_w`, `…_yl`, `…_yr`, `…_z`, `[extruder]`, `[extruder1]`.
3. **Драйверы**: `[tmcXXXX …]` для каждого мотора (для экструдеров с платами голов — из пресета головы).
4. **Концевики и датчик автоуровня**: `[carriage xc]`, `[dual_carriage wc]`, `[carriage ylc]`, `[extra_carriage yrc]`, `[probe]`, `[output_pin probe_enable]`, макросы `PROBE_DEPLOY`/`PROBE_STOW`.
5. **Нагреватели и термисторы**, **вентиляторы**, температуры хоста и главной платы.
6. **Дополнения**: подсветка, секции плат голов (акселерометры, датчики температуры), блок ALPS.

Маркеры в файле:

- `опция: # ЗАПОЛНИТЕ: пин по схеме вашей платы` — пин не определён, впишите его, иначе Klipper не запустится;
- `# !!! СВЕРЬТЕ СО СВОЕЙ СХЕМОЙ …` перед блоком — пины подставлены по таблице разъёмов Octopus Pro, проверьте их.

Список пустых пинов также печатается в конце запуска, по секциям.

## Дополнительные модули и пересечения пинов

Модули — файлы из корня репозитория, которые подключаются строкой `[include …]`. Сейчас один: **`chamber_heater.cfg`** («Подогрев термокамеры», Smart Chamber Heater). Добавить следующий — одна строка в `CFG_MODULES` в `lib/vostok_config.sh`.

Для каждого модуля, который ещё не подключён:

| Состояние в `printer.cfg` | Что делает конфигуратор |
|---|---|
| есть активный `[include модуль.cfg]` | пишет «уже подключён», пропускает |
| есть закомментированный include (как в стоковом `printer.cfg`) | при согласии раскомментирует строку |
| include нет | при согласии копирует файл (если его нет) и добавляет include после include электроники (или перед блоком `SAVE_CONFIG`, или в конец) |

Вопрос задаётся по умолчанию с ответом «нет». `--modules chamber_heater|all|none` отвечает без вопроса (имена через запятую). С `-y` и без терминала модули не меняются.

**Проверка пересечений пинов** (`tools/pin_conflicts.py`) читает `printer.cfg` и все его `[include]`, сравнивает пины по плате и ищет пин, который использован в нескольких секциях (учитывает префиксы вида `T0CB:` и знаки `!`, `^`, `~`). Не считается конфликтом: общие линии SPI (`spi_software_*`), повторы внутри одной секции, виртуальные концевики (`probe:z_virtual_endstop`). Проверка выполняется:

- перед подключением модуля: сравнивается конфиг с модулем и без него, значимы только **новые** пересечения. При пересечении модуль не подключается молча: в диалоге спрашивается «всё равно подключить?» (по умолчанию нет), без терминала или с `-y` модуль не подключается;
- после записи конфига: все пересечения выводятся предупреждением.

Пример: при головах без плат голов термисторы голов стоят на `PF4`/`PF5`, и эти же пины использует `chamber_heater.cfg` (`temperature_sensor Chamber_Temperature` и `heater_generic chamber_heater`). Конфигуратор покажет пересечение и не подключит модуль, пока вы не измените пины. Другой пример: `PA0` — `heater_bed` в конфиге под EBB42 и `fan_generic chamber_heater_fan` модуля.

## Резервные копии и безопасность

- Перед записью сохраняются `printer.cfg` и электроника с тем же именем (при чистой установке ещё `printer_base.cfg` и `chamber_heater.cfg`): `*.bak-<ГГГГММДД-ЧЧММСС>` рядом с оригиналами. В режиме «Пропустить» и при подключении модуля копируется `printer.cfg` (только когда файл реально меняется).
- Блок `SAVE_CONFIG` (PID, смещения) у существующего конфига VOSTOK **сохраняется**. При чистой установке (новый `printer.cfg` из main) он остаётся только в резервной копии. Прочие параметры в секциях `[mcu …]` (например, `baud`) при замене набора `[mcu]` не переносятся: serial и `canbus_uuid` берутся из прежних секций.
- **Вернуть прежний конфиг:** `cp printer.cfg.bak-<дата> printer.cfg` (и так же для остальных файлов).
- Сначала запускайте `--dry-run`. Проверять на копии удобно так: `./configure_vostok.sh --printer-data /путь/к/копии`.
- Ничего не выполняется с правами root, служба Klipper не перезапускается: после записи перезапустите её сами.

## Справочник опций

| Опция | Назначение |
|---|---|
| `--main h723\|f446` | главная плата (иначе определит или спросит) |
| `--heads none\|v1.3\|v2\|ebb42` | платы голов по CAN |
| `--alps 0\|1\|2` | число датчиков ALPS |
| `--config-source standard\|user\|generate\|skip` | источник конфига электроники |
| `--electronics ФАЙЛ` | конкретный `electronics_*.cfg` (для `standard`/`user`) |
| `--drivers СПЕК` | драйверы для `generate`: `all=ТИП` или `x=…,w=…,yl=…,yr=…,z=…,e0=…,e1=…` |
| `--reference ФАЙЛ\|none` | эталон пинов и параметров (по умолчанию ваш electronics-файл, при чистой установке — стоковый main) |
| `--modules ИМЕНА` | подключить модули без вопроса: `chamber_heater`, `all` или `none` |
| `--printer-data DIR` | каталог `printer_data` (по умолчанию `~/printer_data`) |
| `--dry-run` | показать, что будет сделано, ничего не менять |
| `-y`, `--yes` | не задавать вопросов, где есть ответ по умолчанию |
| `-V`, `--version` | версия установщика (файл `VERSION`) |
| `-h`, `--help` | справка |

Переменные окружения: `PRINTER_DATA`, `VOSTOK_CFG_LOCAL` (по умолчанию `auto`: если скрипт запущен из клона `vostok_configuration`, файлы берутся из клона; `0` — всегда скачивать `main`; путь — свой каталог), `VOSTOK_CFG_TARBALL` (адрес архива конфигурации).

Скрипт завершается с кодом 1 при ошибке (нет `python3`, нет каталога `printer_data`, не удалось сгенерировать или записать файл) и с 0 в остальных случаях, в том числе при предупреждениях.

## Типовые сценарии

```bash
# 1. Чистая установка без плат голов, все драйверы TMC5160 (пины из стокового main, головы по таблице Octopus)
./configure_vostok.sh --config-source generate --main h723 --heads none --alps 0 --drivers all=5160

# 2. Сменить драйверы на TMC2209: пины и токи берутся из вашего текущего конфига
./configure_vostok.sh --config-source generate --drivers all=2209

# 3. Другая проводка: платы голов EBB42 вместо H36 (при необходимости сначала посмотрите --dry-run)
./configure_vostok.sh --dry-run --config-source generate --heads ebb42 --drivers all=2209

# 4. Только дописать в printer.cfg новую плату ALPS, остальное не трогать
./configure_vostok.sh --config-source skip --alps 2

# 5. Подключить подогрев термокамеры (с проверкой пересечения пинов)
./configure_vostok.sh --config-source skip --modules chamber_heater
```

## Ограничения

- **H723.** Подстановка пинов из стокового main и из таблицы MOTOR4/MOTOR5 рассчитана на Octopus Pro v1.1 H723. Для F446 без собственного конфига пины остаются пустыми (таблица пинов голов действует и для F446, она взята из F446-конфигов).
- **Таблица пинов голов не сверена** с документацией Octopus Pro v1.1 H723: сверяйте со своей проводкой. Знак `dir_pin` и направление моторов проверяйте после первого запуска.
- **`SAVE_CONFIG` не переносится** только при чистой установке поверх чужого или пустого `printer.cfg` (см. выше).
- **ALPS как зонд** требует правки `printer_base.cfg` (блок в конфиге закомментирован).
- В установщике `--skip-flash` пропускает этап конфигурации целиком: значения `[mcu]` берутся из этапа прошивки. Для настройки без прошивки используйте `configure_vostok.sh`.
- Не проверялось на железе: запуск конфигуратора на реальных платах голов H36 и EBB42 и на Octopus Pro F446. Проверялось на копиях каталога конфигурации и в `--dry-run`: все сочетания плат голов и драйверов, разбор результата как конфига Klipper.

## Устройство (для разработчиков)

| Файл | Роль |
|---|---|
| `configure_vostok.sh` | точка входа: разбор опций, определение железа, `stage_config` |
| `lib/vostok_config.sh` | общая библиотека для `install_vostok.sh` и `configure_vostok.sh`: `detect_hardware`, `pick_electronics` (меню источника), `drivers_wizard`, `find_reference`, `gen_custom_electronics`, `print_gen_warnings`, `merge_mcus_into_cfg`, `stage_config`, `stage_modules` |
| `tools/gen_electronics.py` | сборка файла: шаблон + пресеты + драйверы + эталон; вывод `NAME`, `FILL`, `EMPTY`, `WARN` |
| `tools/mcu_merge.py` | дописывание `[mcu …]` (`OK`/`ADD`/`DIFF`/`TODO`), режим `--list` |
| `tools/pin_conflicts.py` | поиск повторяющихся пинов |
| `templates/electronics_blank.cfg` | шаблон с пустыми пинами и маркерами `;;DRIVERS;;`, `;;EXTRAS;;` |
| `templates/boards/*.cfg` | пресеты плат: `octopus_pro`, `octopus_extruders`, `octopus_heads`, `h36_v1.3`, `h36_v2`, `ebb42`, `alps` |
| `templates/drivers/*.cfg` | пресеты драйверов (`{SEC}` — имя секции мотора) |

Как расширять:

- **Новый драйвер**: файл `templates/drivers/tmcNNNN.cfg` и строка в `DRIVER_TYPES`, `DRIVER_FILES`, `DRIVER_TOKEN`, `DRIVER_TITLE` в `gen_electronics.py`, пункт в `drv_pick` в `lib/vostok_config.sh`.
- **Новая плата головы**: файл `templates/boards/<имя>.cfg` с блоками `@@T0@@`/`@@T1@@` и `{M}` вместо имени MCU, значение в `--heads` и функции `head_*` библиотеки.
- **Новый модуль**: строка `"файл.cfg|Название"` в `CFG_MODULES` и сам файл в корне репозитория.

Как тестировать, не затрагивая рабочий конфиг: копируйте `~/printer_data` в временный каталог и запускайте с `--printer-data` или `PRINTER_DATA=`. Проверка генератора: запустить `gen_electronics.py` с `--out-dir` для всех сочетаний `--heads` и `--drivers` и разобрать результат `configparser` (как это делает Klipper).
